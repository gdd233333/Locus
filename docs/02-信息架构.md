# Locus 信息架构

> 定义三模块的数据模型、屏幕结构、导航和交互流程。UiState 数据类是"前端约束业务"的契约——业务层实现必须能填充这些状态。

---

## 1. 数据模型

### 1.1 戒断中心

```kotlin
// Streak 记录
data class StreakRecord(
    val id: Long = 0,
    val startDate: LocalDate,        // 本次 streak 开始日期
    val endDate: LocalDate?,         // null = 进行中
    val isActive: Boolean,           // 是否为当前活跃 streak
)

// 冲动事件
data class UrgeEvent(
    val id: Long = 0,
    val timestamp: Instant,          // 冲动发生时间
    val intensity: UrgeIntensity,    // 强度
    val durationMinutes: Int?,       // 持续时间（分钟后填写）
    val triggerNote: String?,        // 诱因备注（可选）
    val resolved: Boolean,           // 是否已平复
    val resolutionMethod: String?,   // 平复方式（冲浪练习/冷水洗脸/等）
)

enum class UrgeIntensity { MILD, MODERATE, STRONG }

// 每日打卡
data class DailyCheckIn(
    val id: Long = 0,
    val date: LocalDate,
    val mood: Int,                   // 1-5 自评
    val note: String?,               // 今日备注
    val createdAt: Instant,
)
```

### 1.2 灵感行动库

```kotlin
// 活动
data class Activity(
    val id: Long = 0,
    val title: String,               // 活动名称
    val description: String,         // 描述文案
    val durationMinutes: Int,        // 预估时长
    val category: ActivityCategory,
    val tags: List<String>,          // 标签（如"冲动急救""户外""创作"）
    val isBuiltIn: Boolean,          // 内置 or 用户自定义
)

enum class ActivityCategory(
    val displayName: String,
) {
    EMERGENCY("冲动急救"),
    QUICK("5 分钟"),
    MEDIUM("30 分钟"),
    OUTDOOR("出门走走"),
    CREATIVE("动手创作"),
    INPUT("输入"),
    ENVIRONMENT("环境整理"),
    EXPRESSION("表达"),
}
```

### 1.3 时间记录

```kotlin
// 时间日志
data class TimeLog(
    val id: Long = 0,
    val activityName: String,        // 干了什么（用户手动输入或从建议选）

    val endTime: Instant?,           // null = 进行中
    val date: LocalDate,             // 归属日期（跨天则归入开始日）

    val name: String,
    val useCount: Int,               // 使用次数，用于排序建议
)

## 2. 屏幕清单与导航

### 2.1 主导航（底部四 Tab）

```
┌─────────────────────────────────────────┐
│              内容区域                     │
│                                         │
├─────────────────────────────────────────┤
│  [守护]    [灵感]    [记录]    [复盘]     │
└─────────────────────────────────────────┘
```

| Tab | 路由 | 对应屏幕 | 说明 |
|-----|------|---------|------|
| 守护 | `sober` | SoberScreen | 戒断中心，streak + 冲动冲浪 + SOS |
| 灵感 | `inspire` | InspireScreen | 活动推荐卡片列表 |
| 记录 | `timelog` | TimeLogScreen | 时间记录 + 历史条目 |
| 复盘 | `review` | ReviewScreen | 数据复盘（MVP 占位，显示"敬请期待"） |

### 2.2 屏幕层级

```
MainActivity
├── SoberScreen (守护)
│   ├── SOS 急救 → UrgeEmergencySheet (底部弹层)
│   ├── 打卡 → CheckInSheet (底部弹层)
│   └── 冲浪练习 → SurfingExerciseScreen (全屏)
├── InspireScreen (灵感)
│   └── 活动详情 → ActivityDetailSheet (底部弹层)
├── TimeLogScreen (记录)
│   ├── 开始记录 → StartLogSheet (底部弹层，输入活动名)
│   └── 编辑条目 → EditLogSheet (底部弹层)
└── ReviewScreen (复盘，MVP 占位)
```

## 3. 各屏 UI 状态契约

### 3.1 SoberScreen（戒断中心）

data class SoberUiState(

    val isPersonalBest: Boolean,          // 是否个人最佳

```

## 4. 核心交互流程

### 4.1 打卡流程

```
用户点击"打卡守护"
  → CheckInSheet 弹出
  → 用户选择心情（1-5）+ 可选备注
  → 确认 → 保存 DailyCheckIn
  → StreakRecord.endDate 更新为今天（如果 streak 中断则新建）
  → 庆祝动画（琥珀色粒子爆发）
  → SoberUiState.todayCheckedIn = true
```

### 4.2 冲动急救流程

```
用户点击 SOS 按钮
  → UrgeEmergencySheet 弹出（全屏底部弹层）
  → 显示三个选项：
    1. "我只是记录一下" → 记录 UrgeEvent → 关闭
    2. "我要做冲浪练习" → 跳转 SurfingExerciseScreen
    3. "给我找点事做" → 跳转到 InspireScreen（预筛选"冲动急救"分类）
  → 冲动结束后，用户回到 SoberScreen 标记"已平复"
  → 更新 UrgeEvent.resolved = true, durationMinutes
```

### 4.3 时间记录流程

```
开始记录：
  用户点击"开始记录"
    → StartLogSheet 弹出
    → 输入框 + 常用活动建议 chips
    → 确认 → 创建 TimeLog(startTime = now, endTime = null)
    → RecordingCard 出现，开始实时计时

结束记录：
  用户点击"结束记录"
    → TimeLog.endTime = now
    → RecordingCard 消失
    → 该条目出现在历史记录列表，显示总时长

空闲状态：
  无进行中记录时，显示 IdleCard（虚线边框 + "开始记录"按钮）
```

### 4.4 摇一摇换活动流程

```
用户摇动手机（加速度传感器检测）或点击"换一批"
  → InspireUiState.isShuffling = true
  → 卡片列表执行退出动画（stagger 50ms，translateY + fade）
  → 从活动中随机抽取 3 个（符合当前筛选条件）
  → InspireUiState.activities 更新
  → 新卡片列表执行入场动画（stagger 100ms，fadeUp）
  → InspireUiState.isShuffling = false
```

## 5. Repository 接口（业务层契约）

```kotlin
interface StreakRepository {
    fun getCurrentStreak(): Flow<StreakRecord?>
    suspend fun checkIn(checkIn: DailyCheckIn)
    fun getTodayCheckIn(): Flow<DailyCheckIn?>
    suspend fun logUrge(event: UrgeEvent)
    fun getTodayUrges(): Flow<List<UrgeEvent>>
    fun getRecentUrgeIntensities(days: Int): Flow<List<Float>>
}

interface ActivityRepository {
    fun getActivities(category: ActivityCategory?): Flow<List<Activity>>
    suspend fun getRandomActivities(count: Int, category: ActivityCategory?): List<Activity>
    suspend fun addCustomActivity(activity: Activity)
    suspend fun markCompleted(activityId: Long)
}

interface TimeLogRepository {
    fun getActiveLog(): Flow<TimeLog?>
    fun getLogsForDate(date: LocalDate): Flow<List<TimeLog>>
    suspend fun startLog(activityName: String): TimeLog
    suspend fun endLog(logId: Long)
    suspend fun updateLog(log: TimeLog)
    suspend fun deleteLog(logId: Long)
    fun getFrequentActivities(limit: Int): Flow<List<FrequentActivity>>
}
```

## 6. 数据库 Schema（Room）

```
streak_records:   id, start_date, end_date, is_active
urge_events:      id, timestamp, intensity, duration_minutes, trigger_note, resolved, resolution_method
daily_check_ins:  id, date, mood, note, created_at
activities:       id, title, description, duration_minutes, category, tags, is_built_in
time_logs:        id, activity_name, start_time, end_time, date
frequent_activities: name, use_count  (由 time_logs 聚合生成，非独立表)
```
